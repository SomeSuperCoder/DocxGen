# Подключение ботов ВК и MAX

Код ботов готов: оба работают внутри `pnpm dev` и используют один и тот же диалог. Нужно только создать ботов на платформах и заполнить `.env`.

## ВК — сообщество с ботом

Для локальной проверки нужен только Long Poll: домен и HTTPS не нужны.

1. **Сообщество.** vk.com → «Сообщества» → «Создать сообщество» (подойдёт «Группа по интересам»). Название — «Документ за 3 шага», заполните описание и аватар.
2. **Сообщения.** «Управление» → «Сообщения» → «Сообщения сообщества: Включены». Приветствие: «Оформлю служебный документ за 3 шага».
3. **Возможности ботов.** «Управление» → «Сообщения» → «Настройки для бота»:
   - «Возможности ботов: Включены»;
   - «Добавить кнопку „Начать“» — отметить.
4. **Ключ доступа.** «Управление» → «Работа с API» → «Ключи доступа» → «Создать ключ». Нужные права (в новом интерфейсе они так и называются в строке «Права доступа»):
   - «сообщения сообщества»;
   - «файлы» — для отправки DOCX (в старом интерфейсе — «документы»);
   - «фотографии» — для превью шаблонов;
   - «управление сообществом» — для Long Poll (`groups.getLongPollServer`).

   Ключ → `VK_TOKEN`. ID сообщества (число из «Управление» → «Адрес» или из ссылки club123456) → `VK_GROUP_ID`.
5. **Long Poll API.** «Работа с API» → вкладка «Long Poll API»:
   - подвкладка «Настройки»: «Long Poll API: Включено», версия API **5.199**;
   - подвкладка «Типы событий»: в блоке «Сообщения» отметьте **«Входящее сообщение»**. Без этой галочки бот не получает ни одного сообщения. Остальные типы не нужны.

   Сервер во вкладке «Callback API» для локальной работы не нужен: пока адрес не подтверждён, ВК туда ничего не отправляет.
6. **`.env`:**
   ```
   VK_ENABLED=1
   VK_MODE=longpoll
   VK_GROUP_ID=123456789
   VK_TOKEN=vk1.a.…
   ```
7. **Проверка.** `pnpm dev` → со своего личного аккаунта откройте сообщество → «Написать сообщение» → «Начать». Бот ответит приветствием и кнопкой «Создать документ».

Если бот молчит:
- ошибка `15`/`7` в логе — у ключа нет нужного права (п. 4);
- ошибка `901` — пользователь не разрешил сообщения от сообщества: нажмите «Разрешить сообщения» в диалоге;
- для отладки `pnpm --filter @docxgen/backend vk:poll` печатает сырые события — остановите `pnpm dev`, чтобы события не забирали два процесса.

### ВК на сервере (для экспертов)

Вместо Long Poll используется Callback API — нужен HTTPS-домен.

1. «Работа с API» → «Callback API»: версия **5.199**, адрес `https://<домен>/integrations/vk/callback`, «Секретный ключ» — придумайте → `VK_CALLBACK_SECRET`.
2. Строку «Строка, которую должен вернуть сервер» → `VK_CONFIRMATION_CODE`.
3. «Типы событий» → «Входящее сообщение».
4. `.env`: `VK_MODE=callback`, перезапустите сервер, затем нажмите «Подтвердить» в настройках — статус должен стать «Работает».
5. Long Poll API в настройках выключите, чтобы события не обрабатывались дважды.

Эксперты пишут в сообщество со своих аккаунтов — дополнительный доступ не нужен. Ссылку на сообщество укажите в README и на слайде.

## MAX — чат-бот

1. **Доступ к платформе.** Боты MAX создаются на платформе для партнёров (business.max.ru). Подключение доступно юрлицам, ИП и самозанятым — резидентам РФ. Если у команды нет такого профиля, уточните у организаторов, дают ли они готовый доступ.
2. **Создание бота.** В кабинете: «Чат-боты» → «Создать бота». Задайте:
   - имя «Документ за 3 шага»;
   - ник (по нему бота найдут);
   - описание: «Оформлю служебный документ за 3 шага: черновик → тип и шаблон → файл Word».

   Отправьте бота на модерацию сразу: до её прохождения пользователи вне организации могут не найти бота. Уточните, могут ли эксперты писать ему раньше.
3. **Токен.** В настройках бота, раздел «Интеграция» → «Получить токен» → `MAX_TOKEN`. Токен передаётся в заголовке `Authorization` и хранится только в `.env`.
4. **`.env` для локальной проверки (long polling):**
   ```
   MAX_ENABLED=1
   MAX_MODE=polling
   MAX_TOKEN=…
   ```
   Сертификат: API MAX работает на сертификате удостоверяющего центра Минцифры («Russian Trusted Root CA»), которого нет в Node.js и Windows. Без него любой запрос падает с `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Корневой сертификат лежит в `packages/backend/certs/russian_trusted_root_ca.pem` (скачан с официального источника gosuslugi.ru/crt, SHA-256 `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`, действует до 2032 года). Его подключает `MAX_CA_FILE=certs/russian_trusted_root_ca.pem` (путь считается от `packages/backend`) — доверие добавляется только в процессе приложения, системное хранилище не меняется.
5. **Проверка токена:** `pnpm max:subscribe -- --me` — должны прийти имя и ник бота. Если раньше создавался вебхук: `pnpm max:subscribe -- --delete` (при активном вебхуке long polling не получает событий).
6. **Проверка диалога:** `pnpm dev` → найдите бота в MAX по нику → «Начать».

### MAX на сервере (для экспертов)

MAX рекомендует вебхук: только HTTPS на порту 443 с сертификатом доверенного центра (Let's Encrypt через Caddy подходит, самоподписанный — нет).

1. `.env`: `MAX_MODE=webhook`, `PUBLIC_URL=https://<домен>`, `MAX_WEBHOOK_SECRET` — 5–256 символов `A-Za-z0-9_-`.
2. После запуска сервера: `pnpm max:subscribe`, затем проверка — `pnpm max:subscribe -- --list`.
3. `GET https://<домен>/health` должен показать `max.subscribed: true`. MAX отключает подписку после 8 часов неудачных доставок — проверьте `/health` перед демонстрацией.

## Что проверить в обоих мессенджерах

Пройдите сценарии 1–6 из README на телефоне и компьютере. Отдельно проверьте:
- DOCX скачивается из сообщения и открывается в Word с кириллицей в имени файла;
- в MAX после нажатия кнопки под файлом («Другой шаблон») сам файл остаётся в переписке;
- двойное нажатие кнопки не создаёт дублей, нажатие старой кнопки отвечает «Эта кнопка относится к предыдущему шагу»;
- два аккаунта одновременно проходят сценарий, и их черновики не смешиваются.
