# Диалоговый движок ботов

Общая логика бота «Документ за 3 шага» для всех мессенджеров. Движок ничего не знает о MAX или ВК: он получает нормализованные события от адаптеров ([src/adapters](../adapters/common/README.md)) и возвращает массив ответов. Документы создаются через тот же `documentService`, что и в веб-версии.

## Поток события

```
адаптер ─► dispatcher.accept()  сохранить событие, отбросить дубликат
        └► dispatcher.run()     блокировка диалога → проверка версии кнопки → flow → sendReplies → адаптер
notifier                        опрос статуса документа → flow.onDocumentEvent → ответ пользователю
```

## Модули

| Файл | Назначение |
|------|------------|
| `dispatcher.js` | Вход для всех событий. Дедупликация (`INSERT OR IGNORE` в `inbound_events`), блокировка на диалог, отсев нажатий устаревших кнопок, маршрутизация во flow, восстановление необработанных событий после рестарта (`recover`) |
| `flow.js` | Конечный автомат диалога: принимает событие и возвращает ответы, сам ничего не отправляет |
| `conversations.js` | Хранение состояния диалога в SQLite |
| `lock.js` | Последовательная обработка событий одного диалога |
| `notifier.js` | Опрашивает статус документов раз в `DOCUMENT_POLL_INTERVAL_MS` (5 с) и передаёт результат ИИ-обработки в диалог |
| `keyboards.js` | Наборы кнопок для каждого шага |
| `payload.js` | Компактное кодирование действия кнопки `{ a, v, r }` (действие, значение, версия состояния) |
| `texts.js` | Все тексты бота в HTML, значения экранируются |
| `sendReplies.js` | Передаёт ответы адаптеру |

## Состояния

```
idle → collecting → choose_type → choose_template → processing
processing → ai_failed | confirm_warnings | asking_field | delivering
confirming_warnings → asking_field | delivering | processing | editing
asking_field → asking_field | delivering
delivering → ready          delivery_failed → ready | delivery_failed
ready → choose_template | choose_type | editing
editing → delivering
```

Каждый переход увеличивает `stateVersion`. Версия зашита в полезную нагрузку кнопки, поэтому нажатие старой кнопки после смены шага игнорируется.

## Сценарий пользователя

1. `/start` — приветствие с иллюстрацией.
2. Черновик: текст одним или несколькими сообщениями, в ВК можно голосом.
3. Выбор типа документа и шаблона оформления кнопками.
4. ИИ исправляет текст и извлекает реквизиты. Бот предупреждает о сомнительных полях и спрашивает недостающие по одному.
5. Бот присылает готовый DOCX. Дальше можно сменить шаблон или тип, отредактировать документ или начать новый.

В MAX бот дополнительно предлагает открыть веб-версию как мини-приложение.

## Команды

| Команда | Действие |
|---------|----------|
| `/start`, «Начать» | Начать диалог |
| `/new`, «Новый документ» | Сбросить и начать новый документ |
| `/help`, «Помощь» | Справка |
| `/ai_fail` | Имитация сбоя ИИ (только при `DEBUG_COMMANDS=1`) |
